## 一、为什么 V1 不防女巫

V1 的抽签是**等概率**：`eligible` 池里每个地址权重相同，Fisher–Yates 洗牌后取前 quota 个。

攻击成本几乎为零：

| 攻击方式 | V1 的结果 |
|---|---|
| 1 个人注册 5 个钱包 | 中签概率 ×5 |
| 批量提交占位再放弃（不揭示） | 无任何成本，白占名额、拉低他人中签率 |
| 抢跑 / 批量提交骚扰 | 只需 gas，无经济门槛 |

**实测对照（本轮测试，等概率模式）**：5 个小号（各 0.01 质押，合计 0.1）对阵 1 个诚实地址（0.01），
6 轮里攻击方赢 **4 轮**——地址数量直接换胜率，这正是女巫漏洞。

## 二、V2 的两层防御

### 第 1 层：保证金（bond）—— 让「占位不给钱」变成亏本生意

```solidity
commit(dropId, commitment) payable:
    require(msg.value >= price + bond, "underpaid");
    uint256 stake = msg.value - bond;      // 质押 = 报价，权重来源
```

- **提交时**必须随单缴纳 `bond`；
- **揭示时**立即全额退还 `bond`（`Revealed(..., bondRefunded)` 事件可查）；
- **不揭示**则 `bond` 永久没收，在 `draw()` 时并入发行方 `proceeds`。

效果：批量小号要真金白银占位，且**必须走完揭示**才能拿回保证金。批量 spam 从「免费」变成「每单固定成本」。

### 第 2 层：质押加权抽签（weighted）—— 拆分小号不增加任何权重

```solidity
weights[i] = stakeOf[dropId][eligible[i]];
totalWeight = Σ weights;
// 无放回累积权重采样，重复 k 次
x = seed % totalWeight;
按 x 落在哪个累积区间选出赢家，然后 weights[winner] = 0; totalWeight -= w;
```

关键性质：**权重正比于质押额，与地址数量无关**。
把 0.1 MON 拆成 5 个 0.02 的小号，总权重仍是 0.1 —— `splitting gains nothing`（女巫中性）。

- 复杂度 `O(k·n)`（k = quota，n = 揭示人数），适配中小规模发售；
- `weighted = false` 保留等概率模式，适合社区活动（要「人人同权」，不要「多押多得」）。

### 资金账目（已逐场核对）

```
proceeds = Σ 中签者质押 + (committedCount − revealedCount) × bond
claimRefund：未中签者（含未揭示者）退回质押，保证金不退
sweep：仅发行方可提 proceeds，且 require(amount > 0)
```

## 三、测试覆盖（71 项断言）

| 组 | 内容 | 结果 |
|---|---|---|
| **组 1** 等概率生命周期 | 5 人提交 / 4 人揭示（1 人故意不揭示）/ 开奖 2 中签 / 3 人退款 / 发行方提款；`proceeds = 2×0.01 + 1×0.005 = 0.025` 逐项核对 | ✅ |
| **组 1** 非法操作 | 重复提交、金额不足、等概率模式超额质押、窗口前揭示、错误 secret、重复揭示、非提交者揭示、窗口前开奖、重复退款、中签者退款、非发行方提款、重复提款、开奖前退款 | ✅ 13 项全部正确回退 |
| **组 2** 加权女巫中性 | 5 小号（合计权重 0.1）vs 1 地址（权重 0.1），6 轮抽样 | ✅ 双方 4:2，无一方横扫；总权重严格相等 |
| **组 3** 等概率对照 | 同规模对手，6 轮 | ✅ 攻击方 4/6 胜 —— 漏洞真实存在，加权是解法 |
| **组 4** 边界 | quota(10) > 揭示人数(2) → 全员中签；全员不揭示 → 0 中签、保证金全没收；未揭示者只退质押；不存在 drop / quota=0 / 窗口过短 / price=0 创建 | ✅ |
| **账目核对** | 事件总账：Σ流入 − Σ流出 == 合约余额（逐 wei 相等）；每场「未退质押 + 待提 proceeds」等式 | ✅ |

### 随机性说明（已知限制，口径同 V1）

种子来源：`keccak256(prevrandao, blockhash(number−1), dropId, n, address(this))`，
每场再以 `keccak256(seed, 序号)` 逐次推进。

- 好处：任何人可验证、无中心化服务；
- 限制：验证者/区块生产者理论上可影响 `prevrandao`；**高价值发售应接 VRF**（如 Chainlink VRF / Pyth Entropy），接口只需替换 `_seed()` 一处。

## 四、复现测试

```bash
cd blitzfair-remote
V2_ADDR=0xA90818C1c4557619De96BeEAb3E3A52BeC82B84A node scripts/test-v2.js         # 全量（6 轮 × 2 模式）
node scripts/test-v2.js --fast                                                    # 快速（3 轮）
node scripts/test-v2.js --lean                                                    # 省钱（4 轮，复用钱包）
```

**Monad 测试网三个坑（已写进脚本注释，避免踩第二次）**：

1. **同一账户不能有 pending 排队**：nonce 领先的交易立即回退 → 测试采用「轮次模型」，每轮每钱包只发 1 笔；
2. **按 `gasLimit` 计费**（`gasUsed` 回显 `gasLimit`）→ gasLimit 必须贴近真实值（+15%）才不浪费；
3. **公共 RPC 会 429** → 全局 `withRetry` 指数退避 + 广播间隔。

## 五、已知取舍

| 项 | 现状 | 可选升级 |
|---|---|---|
| 随机性 | 区块字段（可验证、非 VRF） | 接 VRF，替换 `_seed()` |
| 加权抽签复杂度 | `O(k·n)`，适合 n ≤ 数千 | 大规模改「累积权重树 / 排序抽样」 |
| 女巫身份 | 靠「质押权重 + 保证金」经济抑制，非身份认证 | 引入 PoP（人格证明）/ 白名单 |
| 保证金比例 | 由发行方设置（建议 = 5%–20% 质押） | 可加「早鸟折扣 / 迟到加价」 |
| 退款 | 需用户主动 `claimRefund`（pull 模式） | 可选 push（gas 更高、更易被 DOS） |
